# 05 — 导入与发现页安装改为建链

**Type:** grilling · **Blocked by:** 02 · **Status:** resolved（2026-08-23）· **Claimed by:** zcode-session（2026-08-23）

**GitHub issue:** [#16](https://github.com/wenren93/fanbox/issues/16)（母票 [#11](https://github.com/wenren93/fanbox/issues/11)）· **Resolution:** [issuecomment-5384524736](https://github.com/wenren93/fanbox/issues/16#issuecomment-5384524736)

## Question

「导入」和「发现页安装（skills.sh）」在链模型下各自变成什么动作？与用户对谈收敛。

待收敛的具体决策：

1. **跨 agent 分发的形态**：旧「导入 = 从一个安装项拷贝到另一个 agent」是否退役，被「图标点选建链」完全取代？「导入到…」对话框（单选 radio）还要不要留，还是行内图标即全部？
2. **收编为正本**：需要保留的反而是「把外部拷贝收进正本仓」的动作（从 `.cc-switch`、项目级、ZIP 等来源）——这是新「导入」吗？风险检查（docs/15 的静态检查）适用范围是否扩展到收编场景。
3. **发现页安装**：装 = 正本入 `~/.agents/skills`（固定版本解包 + 风险检查不变）+ 默认为选中的 agent 建链。默认勾选哪些 agent（复用现有 defaultTargetAgent 设置，改为多选）？装完正本但一条链都不建是否合法（纯库存）。
4. **同源更新的语义变化**：拷贝模型下更新=逐个安装项替换；链模型下改正本即全 agent 即时生效——「固定版本」原则与「一处更新处处生效」的张力怎么摆（更新正本前是否提示影响 N 个 agent；回滚=恢复旧正本目录）。
5. **卸载语义**：卸载 = 删正本 + 删全部链（trash 可恢复）？只删某 agent 的链算「卸载」还是「取消接入」？词怎么叫。
6. **风险检查与链接安全**：链本身无新内容，检查只针对正本内容；「残留文件」判定（agent 目录里非链非正本名的实体）在链模型下怎么定义。

产出：两个流程的决策清单，供 06 号票落接口、07 号票成文。

## Resolution（2026-08-23，与用户对谈收敛，六项全按推荐拍板）

**流程一：收编（旧「导入」的继任者）**

1. **跨 agent 分发 = 行内图标，拷贝导入彻底退役**：旧「导入到…」对话框（单选 radio）与 `/api/skills/import` 拷贝路径删除；批量场景由 04 号票的批量列操作覆盖。拷贝式跨 agent 分发在新模型中不复存在。
2. **「导入」一词让位给收编**：行详情提供「收编为正本」常驻入口，来源为各 agent 目录的残留拷贝、项目级目录等正本仓之外的本机内容；收编执行与安装**同一套** docs/15 静态风险检查（检查对象是内容本身，与来源无关）。

**流程二：发现页安装（skills.sh）**

3. **装 = 正本入仓 + 默认全选接入**：固定版本解包 + 风险检查不变 → 正本入 `~/.agents/skills` → 按所选 agent 建接入（Claude 建链 / WorkBuddy 拷贝 / Codex 与 ZCode 确保未被配置禁用）。`defaultTargetAgent` 由单选改**多选**、默认全选四 agent；允许全不选 = **纯库存**（此时需为 Codex/ZCode 写禁用配置，因为它们原生扫描正本仓）。
4. **同源更新 = 原子换位 + 影响面提示**：固定版本重新解包 → 临时副本 → 原子换位替换正本；执行前提示「将影响已接入的 N 个 agent」；旧正本进 trash，回滚 = 恢复旧正本目录；链全程不动，全部接入即时生效。
5. **卸载两级**：点灰图标 = **取消接入**（只删该列接入、正本不动）；**卸载** = 正本级动作，正本 + 全部接入一起删除、全部进 trash 可恢复；外部正本只取消接入不删内容（CONTEXT.md「卸载」词条已有此分层）。
6. **风险检查只在「成为正本的时刻」执行**：安装与收编共用同一套检查；软链/接入本身不检查。**残留**（新定义）= agent skill 目录中不属于任何接入的本地实体，是收编或清理的对象，存量清理归 03 号票。
