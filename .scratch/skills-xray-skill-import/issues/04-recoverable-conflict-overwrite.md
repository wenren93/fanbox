# 04 — 完成可恢复的内容冲突覆盖

**What to build:** 让用户在目标同目录名但内容不同时，通过简洁弹窗决定取消或完整覆盖。确认覆盖后目标与来源完全一致，旧目标进入系统废纸篓；取消或任何失败都不会损坏来源和原目标。

**Blocked by:** 03 — 识别相同安装项与名称歧义

**Status:** ready-for-agent

- [ ] 首次请求发现内容冲突时只返回结构化冲突、目标位置和内容指纹，来源与目标均保持不变。
- [ ] 页面仅对结构化内容冲突展示确认弹窗，文案简洁说明来源、目标、完整替换、不合并和原内容可恢复。
- [ ] 弹窗按钮明确为“取消”和“覆盖”，默认焦点为“取消”；取消不发送覆盖请求且不产生写操作。
- [ ] 确认覆盖使用显式覆盖意图和冲突指纹发起第二阶段请求。
- [ ] 覆盖是完整目录替换，旧目标独有而来源没有的文件不会残留在新目标中。
- [ ] 覆盖前构建并验证完整临时目标，再把旧目标移到回滚位置、原子换入新目标，最后把旧目标移入系统废纸篓。
- [ ] 复制、换位或废纸篓任一步失败时恢复原目标，清理临时与回滚内容，并返回简洁错误。
- [ ] 覆盖不会修改来源、来源启停状态或 Claude/Codex 启停配置，也不会重启 Agent。
- [ ] 通过真实 HTTP 接口测试冲突无副作用、取消、完整替换、旧目标可恢复及各阶段失败回滚；前端行为测试覆盖弹窗焦点、按钮和两阶段请求。
