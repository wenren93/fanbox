# 05 — 防止并发覆盖并完成真实验收

**What to build:** 在来源或目标可能被其他 Agent 同时修改的情况下，让导入始终基于执行时最新状态并安全中止过期覆盖；收尾所有忙碌、反馈和视图保持行为，并在重启后的 FanBox 中完成真实交互与视觉验收。

**Blocked by:** 04 — 完成可恢复的内容冲突覆盖

**Status:** ready-for-agent

- [ ] 每次导入及覆盖重试都重新扫描来源并读取最新内容，不盲用页面旧快照。
- [ ] 用户确认覆盖后若目标内容指纹已变化，返回稳定的并发变化状态并提示“目标内容已变化，请重试”，不覆盖最新修改。
- [ ] 若目标在无冲突预检后被外部创建或修改，操作安全中止并按最新状态报告，不留下半成品。
- [ ] 导入与现有启用、停用、卸载操作共用 Skills 写队列；并发请求产生确定结果，不发生缓存授权错位。
- [ ] UI 忙碌期间锁定导入相关按钮，防止重复提交；完成后维持来源展开、搜索、排序和筛选状态。
- [ ] 成功、相同内容、名称歧义、安全拒绝、覆盖失败和并发变化均使用简洁提示，并提供必要的下一步。
- [ ] 自动化测试覆盖并发导入、导入与启停或卸载交错、确认后外部修改，以及不存在扫描可见临时安装项。
- [ ] 实现与自动化测试完成后重启 FanBox，使新接口和页面逻辑生效。
- [ ] 使用 `ego-browser` 验收普通导入、相同内容、名称歧义、取消覆盖、确认覆盖和并发变化；确认默认焦点在取消、弹窗没有不必要技术细节、刷新后视图不跳转。
- [ ] 验收发现的功能、交互或视觉回归在本 ticket 内修复并重新验证，最终结果符合本地规格与独立复制 ADR。
