# 01 — 发现页签与基础搜索

**What to build:** 在 Skills 透视中交付第一条可演示的“发现”路径：用户可在“已安装 / 发现”两个顶层页签之间切换，显式提交关键词后从 skills.sh 查看最多 20 个 Skill 条目，同时始终知道这些条目尚未安装且来自外部服务。现有本机 Skill 安装项的筛选、排序、搜索、展开和批量状态不因页签切换而丢失。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] Skills 透视显示“已安装 / 发现”两个顶层页签，默认进入“已安装”，两类数据不混入同一列表。
- [ ] 切换到“发现”后显示独立搜索框和常驻隐私提示，明确搜索词会从本机发送给 skills.sh。
- [ ] 只有按回车或点击“搜索”才发起请求；输入法组合期间不会发送半截中文查询，也不做逐字实时搜索。
- [ ] 本地服务通过单一可替换的数据源边界访问 skills.sh 匿名搜索接口，查询经过长度限制并固定最多请求 20 条。
- [ ] 上游响应经过严格结构校验，结果保持上游顺序，并只暴露可靠字段：条目标识、名称、来源仓库和安装量。
- [ ] 每个结果明确显示“尚未检查”，提供“检查并安装”和“打开来源”入口，但本票中的安装入口可先说明后续能力尚未完成。
- [ ] 空查询不联网；合法空结果显示“没有找到”，不与请求失败混淆。
- [ ] 从“发现”切回“已安装”后，本机筛选、排序、搜索、展开项和批量状态保持不变；再返回“发现”时保留本次会话中的查询与结果。
- [ ] skills.sh 搜索失败不会影响“已安装”扫描、启停、卸载、导入或批量管理。
- [ ] 集成测试通过真实本地服务和可控假上游验证请求、响应与页签行为；现有 Skills 测试保持通过。
