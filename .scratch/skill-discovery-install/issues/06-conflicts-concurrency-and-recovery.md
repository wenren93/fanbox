# 06 — 异源冲突、未知安装项与原子恢复

**What to build:** 完成外部安装的冲突与恢复边界：不同来源不能凭同名互相覆盖，旧安装项缺少来源记录时需要明确处置，多窗口和安装期间的内容变化不会造成错误替换，文件与来源记录始终共同成功或共同回滚。

**Blocked by:** 05 — 同源更新与本地修改保护

**Status:** ready-for-agent

- [ ] 目标 Agent 已存在相同 Skill 名称但来源身份不同的安装项时，阻止直接安装并提供定位现有安装项的动作。
- [ ] 目标目录存在但没有 FanBox 来源记录时，作为未知冲突展示；用户未明确确认不得覆盖。
- [ ] 用户确认覆盖未知安装项时，原目录移入系统废纸篓，新来源记录只在新安装成功后建立。
- [ ] 来源记录缺失、损坏或被删除不会影响既有 Skill 使用，只会失去自动识别同源更新的能力。
- [ ] 下载和风险检查在 Skills 写队列外完成；最终目标预检、暂存、换位和来源记录写入在现有串行写队列内完成。
- [ ] 最终写入前重新扫描目标并核对检查阶段记录的来源、目标和内容指纹；并发变化返回结构化冲突，不使用过期确认继续覆盖。
- [ ] 多窗口同时安装、更新、导入、启停、卸载或批量操作时，最终文件写入按队列串行执行。
- [ ] 替换采用完整临时同级副本和原子换位；扫描器不会看到临时目录或半完成安装项。
- [ ] 文件与 FanBox 来源记录共同提交；在文件换位、废纸篓移动或元数据写入任一阶段注入失败时，旧文件和旧记录均恢复。
- [ ] 卸载外部安装项时同步移除其来源记录，安装项仍进入系统废纸篓而非永久删除。
- [ ] 成功或失败后都清理下载、解包、暂存与回滚临时内容，不留下可见残留项。
- [ ] 测试覆盖同名异源、未知来源覆盖、来源记录丢失、多窗口竞态、来源变化、目标变化、各阶段失败注入、卸载清理和恢复后的扫描一致性。
