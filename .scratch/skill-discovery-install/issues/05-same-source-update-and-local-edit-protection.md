# 05 — 同源更新与本地修改保护

**What to build:** 让用户能够从“发现”安全地重新安装或更新同一来源身份的 Skill，同时保护安装后发生的本地修改，不让新的远端版本静默覆盖用户工作。

**Blocked by:** 04 — 丰富内容、风险确认与四个目标 Agent

**Status:** ready-for-agent

- [ ] FanBox 以规范公开仓库与 Skill 子目录组成来源身份；名称相同本身不构成更新关系。
- [ ] “发现”再次遇到同一来源身份时，根据固定 commit 显示“重新安装”或“更新”，而不是新的普通安装。
- [ ] 每次重新安装/更新都重新解析当前 HEAD、固定 commit、下载归档并执行全部风险检查，不复用旧版本批准。
- [ ] 目标安装项内容仍与记录哈希一致时，用户确认后可用新固定版本替换旧版本。
- [ ] 目标内容哈希与来源记录不一致时，界面明确标记“本地已修改”，禁止无提示覆盖。
- [ ] 用户查看差异风险并明确确认后，可继续替换本地已修改安装项；原内容移入系统废纸篓，保持可恢复。
- [ ] 新文件与新的仓库、Skill 路径、commit SHA、内容哈希作为一个一致状态切换；任何失败都恢复旧文件和旧来源记录。
- [ ] 同一个 commit 的内容完全一致时返回无需处理，不重复写入或制造废纸篓副本。
- [ ] 不进行后台更新检查、更新通知、定时下载或自动更新；只有用户在“发现”中发起流程才访问新版本。
- [ ] 测试覆盖同源新 commit、同源相同 commit、本地未修改、本地已修改、用户取消、用户确认、替换失败回滚和来源记录一致性。
