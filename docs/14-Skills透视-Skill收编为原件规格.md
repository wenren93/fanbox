# Skills 透视：Skill 收编为原件规格

状态：`ready-for-agent` · 取代旧「Skill 跨 Agent 导入规格」（拷贝式导入已随「原件 + 接入」模型退役，见 ADR 0001）

## Problem Statement

「原件 + 接入」模型建立后，Skill 的全局权威内容只应存在于原件仓 `~/.agents/skills`（及仓库家族、外部工具目录等被引用的原件）。但本机各 Agent 的 Skill 目录里仍散落着不属于任何接入的本地实体——历史拷贝（真实目录）、旧工具残留、外部软链与断链；项目级目录里也有用户验证过、希望提升为全局能力的 Skill。这些内容在行模型中没有归属：它们不是原件，也不是接入。

用户需要把这类内容**收编为原件**：进入原件仓、获得行与图标列、被四个 Agent 接入管理。同时，跨 Agent 分发已不再需要「导入」——点亮行内 agent 图标即是全部（见 docs/16）；本规格只负责「原件仓之外的本机内容如何成为原件」。

收编必须与安装共用同一套风险检查（内容成为原件前必须过检）、结果可预测、失败不损坏来源与现有原件，收编后的来源实体按各列机制改为正规接入，不留双份。

## Solution

在收编对象的详情或异常卡片中提供「收编为原件」动作。FanBox 对来源内容执行与发现页安装完全相同的静态风险检查（拒绝链接、特殊文件与未知可执行二进制，规范化权限），通过后把内容复制到原件仓同级临时位置、原子换位为原件；来源 Agent 目录中的原实体随即按该列机制改为接入（Claude 换相对软链、Codex 删实体靠原生扫描、ZCode 删实体靠原生扫描、WorkBuddy 原目录即拷贝接入），项目级来源保持原样不动。

原件仓已有同名目录时，展示差异概要，用户确认后以收编内容完整覆盖（原子换位，旧目录进系统废纸篓）；被覆盖原件若带有来源身份记录，记录随旧目录一并失效。收编件本身没有来源身份，成为**外来原件**：与安装原件同权管理接入与卸载，但不提供同源更新（见 docs/16 外来原件一节）。

所有写入走现有 Skills 写操作串行队列：预检、临时副本、再次校验、原子换位、失败回滚。收编不自动重启 Agent。

## User Stories

1. 作为多 Agent 用户，我想把某 Agent 目录里的历史拷贝收编为原件，以便它成为全局权威内容并获得图标列管理。
2. 作为用户，我想在异常卡片（真实目录/外部链/断链）上直接发起收编，以便处置扫描发现的残留。
3. 作为用户，我想点亮图标遇到「目标被同名真实目录占用」时被引导到收编流程，以便冲突有明确出路。
4. 作为项目级 Skill 用户，我想从项目级行详情发起收编，以便把项目里验证过的 Skill 提升为全局原件；项目目录保持原样。
5. 作为注重安全的用户，我想让收编执行与安装同一套风险检查，以便任何内容成为原件前都过同一道门。
6. 作为用户，我想让不安全内容（链接、特殊文件、未知可执行二进制）在收编前被拒绝并指出第一个问题路径，以便修复来源后重试。
7. 作为 Skill 作者，我想让脚本可执行权限被规范化保留，以便收编后 Skill 仍可运行。
8. 作为用户，我想让收编完整复制子目录、脚本与资源文件，以便复杂 Skill 收编后可用。
9. 作为用户，我想让来源实体在收编后被正规接入替换（Claude 换链、Codex/ZCode 删实体、WorkBuddy 保留拷贝），以便不留下双份内容。
10. 作为用户，我想让收编前后该列可见性保持不变，以便正在使用该 Skill 的 Agent 不受干扰。
11. 作为 Claude 用户，我想让收编把 Claude 目录里的真实目录替换为相对软链，以便 Claude 语义与全局链接风格一致。
12. 作为用户，我想在原件仓已有同名原件时看到差异概要（来源、目标、修改时间、差异要点），以便判断是否覆盖。
13. 作为谨慎的用户，我想让覆盖确认默认聚焦取消、按钮语义明确，以免误触替换。
14. 作为用户，我想让被覆盖的旧原件进入系统废纸篓，以便需要时恢复。
15. 作为用户，我想明确知道覆盖是完整替换而非合并，以免旧内容残留。
16. 作为用户，我想让收编件在行内以「本机收编」来源标识呈现，以便与安装原件区分。
17. 作为用户，我想让收编件照常支持接入、取消接入与卸载，以便外来身份不降低管理能力。
18. 作为用户，我想让收编件不出现同源更新入口，以便界面不暗示不存在的更新路径。
19. 作为用户，我想在收编失败时来源与原件仓都保持原样，以便安全重试。
20. 作为用户，我想让临时内容在失败后被清理，以免原件仓出现垃圾目录。
21. 作为多窗口用户，我想让并发收编与其他 Skills 写操作串行执行，以免目录状态互相覆盖。
22. 作为用户，我想让收编来源只能是最新扫描确认过的实体，以免接口被用于复制任意本机目录。
23. 作为用户，我想让路径穿越与伪造来源标识被拒绝，以免越过受控边界。
24. 作为维护者，我想从外部 HTTP 接口层验证收编行为，以便测试覆盖真实扫描与文件系统副作用。
25. 作为发布验收者，我想在真实 FanBox 页面验证异常卡片入口、风险检查反馈、覆盖确认与成功后的行状态，以便确认交互符合规格。

## Implementation Decisions

- 使用项目词汇表中的 `原件`、`原件仓`、`收编`、`外来原件`、`内容冲突`、`覆盖`、`接入`；产品文案不把收编称为导入、复制或移动。
- 收编来源限定为最新扫描清单内的实体：四 Agent 全局目录中的残留（真实目录，经 anomalies 呈现）与项目级目录中的有效 Skill。插件 Skill 不提供收编（插件体系自管）。残留项（无有效 `SKILL.md`）不可收编。
- 入口三处：anomalies 卡片的处置动作；行内列冲突（建链目标被同名真实目录占用）的引导；项目级与插件折叠区行详情的「收编为原件」。
- 新增 `POST /api/skills/annex` 接口，请求携带受控来源标识（agent + name，或项目级 root + name）与可选覆盖意图，纳入现有 Skills 写操作串行队列。服务端只解析扫描清单内的路径，不接受任意绝对路径。
- 风险检查与发现页安装共用同一实现（docs/15）：拒绝绝对路径穿越、软硬链接、设备/FIFO/socket 等特殊条目与未知可执行二进制；普通非可执行二进制资源放行；目录 0755、普通文件 0644、带执行位文件 0755 规范化；不保留所有者、时间戳与扩展属性。脚本在确认页明示，增强确认要求勾选。
- 覆盖采用两阶段协议：首次发现同名原件时返回结构化冲突结果与内容指纹；用户确认后以显式覆盖意图与该指纹重试，服务端再次校验目标未变。
- 接口结果至少区分：成功收编、需要覆盖确认、来源不安全、来源无效、并发变化、失败。业务结果使用稳定的机器可读状态。
- 收编执行顺序：风险检查 → 原件仓同级临时副本 → 校验 → 原子换位入原件仓（如覆盖，旧原件先进废纸篓）→ 来源实体按列改为接入 → 刷新扫描。任一步失败回滚，不留半成品。
- 来源列的接入替换：Claude 删除真实目录并建 `../../.agents/skills/<name>` 相对链；Codex 与 ZCode 删除实体（原件仓原生可见，配置不动）；WorkBuddy 保留原目录作为拷贝接入；项目级来源不改动。
- 收编成功即写入原件行数据（origin 按实际来源），不写来源身份记录；被覆盖旧原件的来源身份记录随文件一并移除。
- 收编完成后自动刷新 Skills 透视，保持当前筛选；成功提示注明该列可见性保持不变、Codex 需重启生效时提示重启。
- 拷贝式跨 Agent 导入（旧 `/api/skills/import`、`SKILL_IMPORT_TARGETS`、目标选择器与「导入到…」入口）随之删除，不在本规格中保留任何兼容形态。
- 功能实现需要重启 FanBox 服务后生效；实现与测试完成后应重启 FanBox，再执行浏览器交互验收。

## Testing Decisions

- 沿用现有 Skills 集成测试 seam：真实服务 + 隔离 HOME 与各 Agent 根 + 公开本地 HTTP 接口，断言响应、文件系统结果与刷新后的扫描结果。
- 测试四 Agent 目录的真实目录残留均可收编：收编后原件入仓、来源列可见性不变、Claude 列为相对链、WorkBuddy 列为拷贝、Codex/ZCode 无残留实体。
- 测试项目级来源收编后项目目录内容与时间戳不变。
- 测试风险检查与安装同一套：链接、特殊文件、未知可执行二进制被拒并返回问题相对路径；脚本触发增强确认；权限规范化生效。
- 测试同名冲突两阶段协议：首次返回结构化冲突与指纹、字节不变；确认覆盖后完整替换、旧原件可从废纸篓恢复、来源身份记录被移除；覆盖后目标被外部修改时返回并发变化。
- 测试失败回滚：临时副本构建、换位、来源替换各阶段可控失败均不损坏来源与现有原件，不留下扫描可见的临时目录。
- 测试并发收编与接入/卸载/安装经同一写队列串行，不出现半成品。
- 测试来源校验：未扫描目录、扫描后消失的来源、路径穿越与伪造标识被拒绝且无副作用；残留项（无有效 SKILL.md）不可收编。
- 前端沿用现有 Skills 透视行为断言：anomalies 卡片入口、冲突引导、覆盖确认默认聚焦取消、机器可读状态到提示的映射、成功后刷新保持筛选。

## Out of Scope

- 恢复或保留拷贝式跨 Agent 导入的任何形态（已由行内图标接入取代）。
- 从 GitHub、URL、压缩包或文件选择器收编（外部内容走发现页安装）。
- 收编外部软链的目标内容（外部原件由其所有者管理，只做接入，见 docs/16）。
- 收编插件 Skill。
- 逐文件合并或差异选择。
- 自动修复来源健康问题。
- 收编时自动重启 Agent。

## Further Notes

- 收编是外来原件的主要产生路径；其并存规则（无同源更新、覆盖接管、健康检查发现外部修改）统一见 docs/16「外来原件」一节，不在本规格重复。
- 存量残留的批量处置属于一次性迁移（docs/16 迁移规格），运行时收编面向迁移之后的增量场景。
- 该规格遵守项目词汇表以及 ADR 0001「Skill 分发使用原件仓与 Agent 接入」。
