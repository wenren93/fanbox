# Skills 透视：Skill 跨 Agent 导入规格

状态：`ready-for-agent`

## Problem Statement

用户在 Claude、Codex、Agents 共享目录、WorkBuddy、项目和插件中积累了不同的 Skill 安装项。Skills 透视目前可以统一查看、启停和卸载这些安装项，却不能把一处已有的 Skill 安装项添加到另一个 Agent。用户只能离开 FanBox 手工寻找目录并复制文件；遇到同名目标时，也难以判断应该跳过、覆盖还是合并，误操作可能留下半份 Skill、旧文件残留或覆盖刚被其他 Agent 修改的内容。

用户需要在 Skills 透视中从一个已扫描的有效 Skill 安装项发起导入，选择一个受支持的目标 Agent，并在发生内容冲突时明确决定是否覆盖。整个过程必须保持来源不变、结果可预测、失败不损坏现有安装项，并使用简洁提示说明必要后果。

## Solution

在每个有效 Skill 安装项的展开详情中增加“导入到…”操作。用户选择 Claude、Codex、Agents 共享目录或 WorkBuddy 的全局 Skill 位置后，FanBox 将来源安装项的完整有效内容一次性复制为目标安装项。来源与目标随后相互独立，不建立软链接或持续同步关系。

目标没有同目录名安装项时直接导入；目标内容与来源完全相同时不重复写入；同目录名但内容不同时，以简洁弹窗询问是否完整覆盖；目标存在目录名不同但 Skill 名称相同的安装项时阻止导入并帮助用户定位歧义项。覆盖绝不进行逐文件合并，原目标安装项移入系统废纸篓并可恢复。

所有写入使用预检、临时副本、再次校验、原子换位和失败回滚。导入不改写 Agent 专属元数据，不改变既有启停配置，不自动重启 Agent。完成后自动刷新 Skills 透视并给出简洁反馈。

## User Stories

1. 作为同时使用多个 Coding Agent 的用户，我想把一个 Agent 独有的 Skill 导入另一个 Agent，以便复用已经安装在本机的能力。
2. 作为 Skills 透视用户，我想从具体 Skill 安装项的详情发起导入，以便无需再次选择来源。
3. 作为 Claude 用户，我想把 Codex 中的 Skill 导入 Claude 全局 Skill 位置，以便新的 Claude 会话可以发现它。
4. 作为 Codex 用户，我想把 Claude 中的 Skill 导入 Codex 全局 Skill 位置，以便新的 Codex 会话可以发现它。
5. 作为多 Agent 用户，我想把 Skill 导入 Agents 共享目录，以便把它作为共享层中的普通安装项管理。
6. 作为 WorkBuddy 用户，我想把其他来源的 Skill 导入 WorkBuddy 全局 Skill 位置，以便 WorkBuddy 可以发现它。
7. 作为用户，我想在一次操作中只选择一个目标 Agent，以便清楚理解本次操作的结果。
8. 作为用户，我想只看到不会落回来源同一目录的目标，以免执行没有意义的自我导入。
9. 作为用户，我想在目标选择器中看到 Agent 名称和实际位置，以便知道新安装项会落在哪里。
10. 作为用户，我想选择尚未创建 Skill 目录的受支持 Agent，以便 FanBox 在确认后代为创建目录。
11. 作为用户，我想从全局安装项导入，以便在其他 Agent 的全局环境中复用它。
12. 作为用户，我想从项目级安装项导入，以便把项目里验证过的 Skill 提升为另一个 Agent 的全局安装项。
13. 作为用户，我想从已停用安装项导入，以便复制其内容而不必先改变来源状态。
14. 作为用户，我想从 Claude 插件提供的安装项导入，以便在其他 Agent 中获得一个可独立管理的普通安装项。
15. 作为插件 Skill 用户，我想明确知道导入结果不再随插件更新，以便理解新安装项的所有权。
16. 作为用户，我想让来源安装项在导入后保持原样，以便导入不会破坏原 Agent 的能力。
17. 作为用户，我想让目标安装项与来源相互独立，以便之后修改任一侧不会暗中改变另一侧。
18. 作为用户，我想完整复制 Skill 的子目录、脚本、引用资料和资源文件，以便复杂 Skill 导入后仍可正常使用。
19. 作为包含可执行脚本的 Skill 作者，我想保留脚本的可执行权限，以便导入后无需手工修复权限。
20. 作为用户，我想让导入忽略所有者、时间戳和 macOS 扩展属性，以免携带机器相关或隔离元数据。
21. 作为用户，我想让目标保留来源中的 Agent 专属配置文件，以便导入过程无损。
22. 作为用户，我不希望 FanBox 自动改写 Claude 或 Codex 的元数据格式，以免未经确认改变 Skill 行为。
23. 作为用户，我想让顶层软链接来源被解析为实际 Skill 内容，以便目标成为真正独立的安装项。
24. 作为用户，我想让安全的内部软链接内容被完整导入，以便目标不依赖来源目录。
25. 作为注重安全的用户，我想阻止指向来源 Skill 目录之外的软链接，以免意外复制隐私文件或无关目录。
26. 作为用户，我想阻止循环软链接，以免导入卡住或无限复制。
27. 作为用户，我想阻止 socket、设备文件和 FIFO 等特殊文件，以免产生不可预测的复制结果。
28. 作为用户，我想在拒绝不安全内容时看到第一个问题路径，以便修复来源 Skill。
29. 作为用户，我想让缺少可读 `SKILL.md` 的残留项没有导入入口，以免创建无效目标安装项。
30. 作为用户，我想在目标不存在同目录名安装项时直接完成导入，以便流程简短。
31. 作为用户，我想在目标已有完全相同内容时看到“已存在”的反馈，以免产生无意义写入和废纸篓备份。
32. 作为用户，我想在目标同目录名但内容不同时收到覆盖确认，以便不会静默丢失现有内容。
33. 作为用户，我想让覆盖弹窗保持简洁，以便快速理解关键后果。
34. 作为用户，我想在覆盖弹窗中看到来源、目标 Agent 和目标位置，以便确认操作对象。
35. 作为用户，我想明确知道覆盖会完整替换而非合并，以免旧目标中的独有文件残留。
36. 作为用户，我想明确知道原目标可恢复，以便放心做出覆盖决定。
37. 作为谨慎的用户，我想让覆盖弹窗默认选择取消，以免误触造成替换。
38. 作为用户，我想用明确的“取消”和“覆盖”按钮做决定，以免含糊的“确定”造成误解。
39. 作为用户，我想在取消覆盖后保持来源和目标完全不变，以便安全退出操作。
40. 作为用户，我想让确认覆盖后的目标与来源完整一致，以便不会发生文件级合并。
41. 作为用户，我想让被替换的原目标安装项进入系统废纸篓，以便需要时可以恢复。
42. 作为用户，我想在目录名不同但 Skill 名称相同时阻止导入，以免 Agent 面对两个同名 Skill 时行为不确定。
43. 作为用户，我想在名称歧义提示中看到冲突安装项及位置，以便找到需要处理的对象。
44. 作为用户，我想从名称歧义提示直接在文件区显示冲突项，以便修改名称或卸载后重试。
45. 作为用户，我不希望名称歧义提示提供强制继续，以免绕过安全边界。
46. 作为用户，我想让导入不改变来源的启停状态，以便复制内容与可见性管理保持独立。
47. 作为用户，我想让导入不主动覆盖目标 Agent 的既有启停配置，以免连带改变其他同名安装项。
48. 作为用户，我想在目标仍受配置停用时得到简洁提示，以便随后自行使用现有开关启用。
49. 作为 Claude 用户，我不希望导入隐式改变所有同名 Claude 安装项的状态，以免扩大操作影响范围。
50. 作为 Codex 用户，我想知道新会话可发现导入结果，而不是误以为当前运行中的会话会立即重新加载。
51. 作为用户，我不希望导入自动重启任何 Agent，以免中断正在进行的工作。
52. 作为用户，我想在导入后自动刷新 Skills 透视，以便立即看到新的目标安装项和跨端状态。
53. 作为用户，我想在刷新后保持来源安装项展开，以便继续当前上下文。
54. 作为用户，我不希望成功后自动改变当前筛选条件，以免界面突然跳走。
55. 作为用户，我不希望成功后自动打开目标安装项，以免打断当前浏览位置。
56. 作为用户，我想收到包含目标 Agent 名称的简洁成功提示，以便确认导入去向。
57. 作为用户，我想收到简洁且可行动的失败提示，以便知道是修复来源、处理冲突还是重新尝试。
58. 作为同时运行终端 Agent 的用户，我想让 FanBox 在最终写入前重新读取来源和目标，以免使用已经过期的页面快照。
59. 作为用户，我想在来源于弹窗打开后被修改时中止或基于新内容重新预检，以免导入与我看到的内容不一致。
60. 作为用户，我想在目标于覆盖确认后再次变化时中止覆盖，以免抹掉其他 Agent 刚写入的内容。
61. 作为用户，我想看到“目标内容已变化，请重试”的提示，以便重新审视最新状态。
62. 作为用户，我想让复制失败时原目标保持可用，以免一次导入损坏已有能力。
63. 作为用户，我想让临时内容在失败后被清理，以免 Skill 根目录残留垃圾安装项。
64. 作为用户，我想让废纸篓操作失败时整个覆盖回滚，以免出现旧目标既不可恢复、目标又不完整的状态。
65. 作为多窗口用户，我想让同时发生的 Skill 写操作按顺序执行，以免互相覆盖扫描依据或目录状态。
66. 作为用户，我想让导入来源只能是最新扫描确认过的安装项，以免接口被用于复制任意本机目录。
67. 作为用户，我想让目标只能是四个受控全局 Skill 位置，以免接口被利用写入任意路径。
68. 作为用户，我想让路径穿越和伪造目标标识被拒绝，以免越过 FanBox 的能力边界。
69. 作为用户，我想让内容一致比较忽略无关元数据但考虑文件内容、结构和可执行权限，以便判断结果符合实际可用性。
70. 作为维护者，我想从外部接口层验证完整导入行为，以便测试覆盖真实扫描、校验和文件系统副作用。
71. 作为维护者，我想对冲突、覆盖、回滚和不安全输入进行集成测试，以便后续重构仍保持安全语义。
72. 作为维护者，我想沿用现有 Skills 透视前端行为测试方式，以便不为单一功能引入新的 UI 测试架构。
73. 作为发布验收者，我想在真实 FanBox 页面验证目标选择、简洁弹窗和反馈，以便确认交互与视觉效果符合规格。

## Implementation Decisions

- 使用项目词汇表中的 `Skill 安装项`、`目标 Agent`、`导入`、`目标安装项`、`内容冲突` 和 `覆盖`；产品文案不把导入称为移动、同步或共享。
- “导入”是一份一次性完整复制。来源安装项保持不变，目标安装项成为独立的普通安装项；该边界遵守“Skill 导入使用独立副本”的架构决策。
- 首版目标 Agent 固定为 Claude、Codex、Agents 共享目录和 WorkBuddy 的全局 Skill 位置。请求只传受控目标标识，服务端自行解析目标根，不接受任意目标绝对路径。
- 一次请求只导入到一个目标 Agent。会落回来源同一目录的目标不出现在选择器中，服务端仍独立拒绝自我导入。
- 全局、项目级、已停用和插件提供的有效 Skill 安装项均可作为来源。残留项不可导入。
- 插件来源经导入后变成普通独立安装项，不再由原插件管理或更新；界面在目标选择过程中以一句简短说明提示该边界。
- 入口位于有效 Skill 安装项的展开详情动作区，名称为“导入到…”。不增加容易被理解为从外部文件导入的全局入口。
- 目标选择器只展示 Agent 名称与实际全局位置；不存在的目标根可在执行时创建。
- 新增一个 Skill 导入 HTTP 接口，并纳入现有 Skills 写操作串行队列。请求包含最新可扫描的来源安装项路径、受控目标 Agent 标识、可选的覆盖意图，以及当前浏览目录用于重新发现项目级来源。
- 覆盖采用两阶段协议：首次发现内容冲突时返回结构化冲突结果和目标内容指纹；用户确认后使用显式覆盖意图与该指纹重试。服务端在重试时再次扫描、校验来源，并验证目标仍与用户确认时一致。
- 接口结果至少区分：成功创建、内容一致无需处理、需要覆盖确认、名称歧义、并发变化、输入或内容不安全、失败。业务结果使用稳定的机器可读状态，界面不靠解析中文错误文案判断流程。
- 来源身份必须来自执行时强制刷新的 Skills 清单。目标身份只由服务端允许列表解析；来源和目标不得解析到同一安装项。
- 有效来源沿用现有扫描模型：候选目录中存在且可读的 `SKILL.md`。导入不借机提高全局 Skill 有效性门槛；已有 frontmatter 或 description 健康问题仍由现有健康检查显示。
- 目标安装项目录名沿用来源安装项目录名。目标已有相同目录名时构成内容冲突；目标没有相同目录名但存在相同 Skill 名称时构成名称歧义。
- 名称歧义不得强制继续。结果包含冲突安装项的身份和位置，界面提供“在文件区显示”。
- 内容比较基于导入后的有效目录树：比较相对路径、条目类型、普通文件字节内容和可执行权限；忽略所有者、时间戳及扩展属性。
- 目标与来源内容一致时返回无需处理，不写文件、不生成废纸篓项目，也不改变目标时间戳。
- 内容冲突弹窗保持简洁，只传达来源、目标、完整替换、不合并、原内容可恢复。按钮为“取消”和“覆盖”，默认焦点为“取消”。
- 覆盖是完整目录替换，不进行逐文件合并；旧目标中来源不存在的文件必须从新目标中消失。
- 复制保留普通文件、目录结构和可执行权限，不保留所有者、时间戳或 macOS 扩展属性。Agent 专属配置和未知普通资源原样复制，不执行格式转换。
- 如果来源安装项本身是软链接，先解析真实 Skill 根并复制实际内容，目标顶层不保留对来源的链接关系。
- 遍历内部软链接时仅允许最终解析结果仍位于真实来源 Skill 根内，并把其有效内容复制进独立目标。外部链接、循环链接以及 socket、设备文件、FIFO 等特殊条目在预检阶段拒绝；结果指出第一个问题相对路径。
- 写入前先在目标根的同级临时位置构建完整目标副本并完成安全遍历与验证。临时名称必须被扫描器忽略，且无论成功或失败都不得成为可见 Skill 安装项。
- 无冲突创建使用同一文件系统内的原子换位把临时副本放到最终目标。若最终位置在预检后出现，操作中止并重新报告最新冲突。
- 覆盖时先验证目标指纹未变化，再把旧目标原子移到同级回滚位置，把临时副本原子换入目标位置，最后把旧目标移入系统废纸篓。任何步骤失败均恢复旧目标并清理临时或回滚内容。
- 导入不调用现有启停操作，也不写入 Claude 或 Codex 的启停配置。目标安装项位于正常全局 Skills 根，但既有按名称或路径配置仍然生效。
- 导入完成后重新扫描 Skills 数据，保持来源详情展开和当前筛选条件。界面不自动定位目标，也不自动重启 Agent。
- 成功提示采用“已导入到 {Agent}；新会话可发现”的简洁形式。如果扫描结果显示目标仍处于停用状态，再追加一句可用现有开关启用。
- 内容一致提示采用“{Agent} 已有相同安装项”；并发变化提示采用“目标内容已变化，请重试”。其他提示保持简短，并提供可以采取的下一步。
- UI 忙碌期间锁定当前导入相关按钮，防止重复提交；取消选择或覆盖不产生写操作。
- 功能实现需要重启 FanBox 服务后生效；实现与测试完成后应重启 FanBox，再执行浏览器交互验收。

## Testing Decisions

- 主要自动化测试 seam 只有一个：通过真实本地 HTTP 接口，在隔离的 HOME 和真实临时目录中观察响应与文件系统结果。测试外部行为，不直接调用内部复制 helper，也不锁定临时目录命名、函数拆分或具体换位步骤。
- 该 seam 沿用现有 Skills 批量管理测试的先例：启动真实服务、构造隔离的 Agent Skill 根、发送 HTTP 请求并验证扫描结果与落盘副作用。
- 测试四种全局目标标识均能被解析，未存在的目标根能够安全创建，并且任意目标路径、未知目标标识和路径穿越均被拒绝且无副作用。
- 测试全局、项目级、已停用和插件安装项均可作为来源；残留项、未扫描目录、扫描后消失的来源不能导入。
- 测试复杂 Skill 的嵌套目录、二进制资源、空目录、普通文件和可执行脚本被完整复制，来源保持不变，目标顶层不是指向来源的软链接。
- 测试复制保留可执行权限，但不依赖所有者、时间戳或扩展属性等非契约元数据。
- 测试安全内部软链接导入后不依赖来源；外部链接、循环链接、socket 和 FIFO 被拒绝，并返回问题相对路径。
- 测试目标不存在时成功创建；刷新后目标作为新的 Skill 安装项出现，并形成正确的跨端安装关系。
- 测试目标内容完全一致时返回无需处理，目标内容及时间戳不变，且不产生废纸篓项目。
- 测试同目录名且内容不同时首次只返回结构化内容冲突，来源和目标字节保持不变。
- 测试显式确认覆盖后进行完整替换：来源缺少的旧目标独有文件必须消失，旧目标可从废纸篓恢复，来源保持不变。
- 测试目录名不同但 Skill 名称相同时返回名称歧义，响应指出冲突安装项，且不创建新目录。
- 测试用户确认冲突后目标被外部修改会返回并发变化，不覆盖新修改。
- 测试来源在选择后被外部修改时使用执行时最新快照进行预检，不盲目使用页面旧数据。
- 测试复制、换位和废纸篓阶段的可控失败均不会损坏原目标，不留下扫描可见的临时安装项。若现有 seam 无法稳定制造某阶段失败，只为文件操作适配层增加最小故障注入点，不另建一套复制模块测试面。
- 测试多个并发导入或导入与现有启停、卸载操作通过同一写队列得到确定结果，不出现半成品或缓存授权错位。
- 测试导入不会修改 Claude 或 Codex 的启停配置，不会主动改变来源状态，也不会产生 Agent 重启副作用。
- 前端沿用现有 Skills 透视行为断言，验证详情存在“导入到…”入口、目标选择排除自我目录、请求使用受控目标标识、只有结构化内容冲突触发覆盖确认、取消不重试、覆盖使用显式确认与冲突指纹重试、名称歧义提供定位动作、忙碌时锁定操作、成功后刷新且保持筛选。
- 前端测试不通过中文错误字符串推断服务端状态，只验证机器可读状态到用户提示的映射。
- 使用 `ego-browser` 在重启后的 FanBox 中做交互与视觉验收，覆盖普通导入、内容一致、简洁覆盖弹窗、取消、确认覆盖、名称歧义和失败提示；检查键盘焦点默认落在取消、弹窗文案没有不必要技术细节、刷新后视图没有跳筛选。

## Out of Scope

- 导入到项目级 Skill 位置。
- 用户自定义或任意 Agent Skill 目录。
- Hermes、OpenClaw、Kimi、ZCode、opencode、pi、CodeBuddy、Qoder 等尚未适配的 Skill 目标。
- 一次导入到多个目标 Agent，或批量选择多个来源安装项。
- 从 GitHub、URL、压缩包、文件选择器、市场或电脑外部来源安装 Skill。
- 在来源与目标之间建立持续同步、双向同步、更新订阅或共享软链接。
- 自动检测来源更新并提示重新导入。
- 合并来源与目标文件，或提供逐文件差异选择。
- 自动改写 `SKILL.md`、frontmatter、Claude 调用策略或 Codex `agents/openai.yaml`。
- 自动修复来源 Skill 的健康问题。
- 导入时自动启用目标安装项、修改 Agent 配置或重启 Agent。
- 为同 Skill 名称的歧义提供强制继续。
- 复制来源目录之外的软链接目标或特殊文件。
- 为本功能新建完整浏览器自动化测试框架。

## Further Notes

- 产品提示文案必须简洁。安全细节由实现和测试保证，弹窗只向用户说明做决定所需的信息。
- Agents 在目标选择器中应明确标注为“共享目录”，避免被误解为一个具体 Agent。
- “新会话可发现”比“立即生效”准确；已有运行中的 Agent 会话不会因目录写入自动重新加载。
- Claude 按 Skill 名称配置启停，Codex 按 `SKILL.md` 绝对路径配置，WorkBuddy 依赖目录位置。导入保持与启停解耦，避免把一次内容复制扩大为隐式状态变更。
- 该规格遵守项目词汇表以及 ADR 0001“Skill 导入使用独立副本”。
