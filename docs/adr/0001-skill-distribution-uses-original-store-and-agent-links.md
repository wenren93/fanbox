# Skill 分发使用原件仓与 Agent 接入（原「独立副本」）

## 状态

已修订（2026-08-23）。本 ADR 取代同一编号下的原决策「Skill 导入使用独立副本」。

## 原决策（2026 年初）

Skills 透视最初采用「导入 = 一次性完整复制」：目标安装项与来源相互独立，不建立软链接或持续同步。当时的理由是所有权与更新边界清晰、实现简单、不依赖符号链接行为。

## 为什么转向

四个 Coding Agent 在本机各自积累了 Skill 目录后，独立副本模型暴露出系统性代价：

- **漂移成为常态**：同一 Skill 在仓库、`~/.agents`、`~/.codex`、`~/.workbuddy` 之间同名不同版，用户无法判断哪份是权威内容（实测 22 个同名跨仓几乎全部漂移）。
- **启停与分发割裂**：跨 Agent 复用一份能力需要逐份拷贝，「导入」对话框只能单选目标，启停又要分别理解各 Agent 的官方配置体系。
- **skills.sh 生态已收敛于原件仓**：官方安装器以 `~/.agents/skills` 为唯一原件、逐 skill 相对软链分发给各 Agent；Codex 与 ZCode 更是原生扫描该目录。FanBox 的拷贝模型与生态事实逆向而行。

## 新决策

每个 Skill 全局只有一份**原件**（链条最终指向的真实目录），FanBox 管理的原件位于原件仓 `~/.agents/skills`；各 Agent 通过**接入**引用原件，接入形态随 Agent 原生机制而异（软链、配置或拷贝，见 ADR 0005）。跨 Agent 分发 = 点亮/熄灭行内 agent 图标，不再存在拷贝式导入；外部内容的进入口收敛为发现页安装（原件入仓 + 按所选 Agent 接入）与收编（把原件仓外的本机拷贝提升为原件）。同源更新只替换原件一次，全部已接入 Agent 同时生效；旧原件进系统废纸篓可恢复。

## 代价与约束

- 原件损坏或误删会同时影响全部已接入 Agent（由废纸篓恢复与同源更新回滚兜底）。
- 相对软链依赖 Unix 语义，Windows 暂不支持（社区移植另行立项）。
- 与第三方安装器（skills.sh CLI、cc-switch、手动 git clone）并存于同一原件仓：外来原件同权管理但无同源更新，冲突走覆盖接管，写入互斥依赖原子换位而非锁（见 docs/16 外来原件一节）。
